# エージェントチームでの不具合究明

症状: $ARGUMENTS

このセッションは社長が `scripts\team.bat bug` で起動したチームのリーダー（部長）です。相手のリポジトリ（../VibeCodingYouTubeAnalysisChrome）も読めます。

1. 仮説を3〜4個立てる（例：YouTube側の仕様変更、取得処理の不具合、解析の境界値、環境・依存の問題）。
2. 仮説ごとにチームメイトを起こす。subagent の定義を使い、名前を付ける：
   - 「app-ops-run のエージェント種別でチームメイト "再現" を起こし、…を再現させる」
   - 「app-dev-model の種別でチームメイト "取得" を起こし、仮説Aを調べさせる」 など
   相手の部の担当が必要なら、相手リポジトリの .claude/agents/ の定義ファイルと CLAUDE.md を読んでから、その役で振る舞うよう指示する。
3. 調査中は、原則として読むだけ・試すだけにし、製品コードは直させない（直すのは通常の /bugfix-pipeline で）。チームメイトどうしで互いの仮説を反証させる。
4. 結論を docs/07_ops/incidents/INC-xxxx-*.md にまとめる：症状、仮説と検証結果、原因、直し方の案、影響範囲。
5. チームメイトを全員終了させる（「〜を終了させて」）。
6. 社長に結論を報告し、修正は通常のセッションで /bugfix-pipeline として進める。両部にまたがるなら、それぞれの部で直す。
