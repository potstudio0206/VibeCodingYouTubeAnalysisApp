# 定期実行の一覧（PC上のローカルタスク）

Claude デスクトップアプリの「Scheduled」で、**ローカル（Only on this computer）** のタスクとして登録します。
- フォルダ：各リポジトリのフォルダ（部長として起動します）
- 権限モード：Auto（使えない場合は、登録後に「Run now」で一度実行し、確認が出た操作に「常に許可」を選ぶ）
- PCとアプリが起動している間だけ動きます。スリープ中に過ぎた予定は、起動後に1回だけ実行されます。
- 時刻は他の予定と重ならないよう、ちょうどの時刻（00分・30分）を避けています。

## アプリケーション部（VibeCodingYouTubeAnalysisApp）
| 名前 | いつ | 内容（プロンプト） |
|---|---|---|
| app-巡回 | 毎日 8:00〜23:00、2時間ごと（7分） | 下の「巡回」 |
| app-日報 | 毎日 20:47 | `/daily-report` を実行してください。 |
| app-実配信確認 | 毎日 10:13 | `/smoke-test` を実行してください。 |
| app-動向調査 | 毎週月曜 9:22 | `/research-scan` を実行してください。 |
| app-試用 | 毎週水曜 14:36 | `/player-session` を実行してください。 |

### 巡回のプロンプト
```
定期の巡回です。次の順に確認してください。
1. 起動時のブリーフィングで、★（社長のコメント）が付いた判断待ちがあれば、決定を取り込んで作業を再開する。
2. 新しい社長指示Issue（ラベル「社長指示」）があれば受け付け、内容に合うスキル（/feature-pipeline、/bugfix-pipeline など）で進める。
3. 進行中の案件で、止まっているもの（手戻り待ち・レビュー待ち）があれば、次の工程に進める。
4. 何もなければ、何もせずに終了する。
社長判断が必要な事項は /escalate で判断待ちIssueにし、その件は止めて他を進めてください。
```

※ cron で書く場合の例（Custom）：巡回 `7 8-22/2 * * *`、日報 `47 20 * * *`。
