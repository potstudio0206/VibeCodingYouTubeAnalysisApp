# 追記：依存の急ぎ確認と2本目のスモークテスト（2026-10-30 夜）
依頼元：部長（動向レポート docs/01_research/trends/2026-10-30.md の急ぎ2件＋tv_samsung 既定化）。ブランチ docs/ops-deps-2026-10-30。

## A. certifi は setup.bat で更新されるか
### 勧告の確認（WebSearch の結果。公式ページそのものは未取得）
- GHSA-6q48-6c7w-9gw2：certifi が、中間CAの秘密鍵が漏れた emSign ルート証明書を含んでいた件。深刻度 Critical（Kodem の表記）。
- 修正版：情報源により 2026.10.18 または 2026.10.19 と食い違う。安全側で 2026.10.19 以上とする（yt-dlp 側の下限も 2026.10.19）。

### 検証（手元PC・Python 3.13.14・pip 26.1.2。使い捨ての仮想環境）
| 手順 | 結果 |
|---|---|
| 仮想環境に certifi==2025.1.31（脆弱な古い版）だけ入れる | certifi 2025.1.31 |
| setup.bat と同じ `pip install -U "yt-dlp[default]"` を実行 | certifi 2026.10.23 に更新された（「Uninstalling certifi-2025.1.31」と表示）。yt-dlp 2026.10.26 |
| 原因 | yt-dlp 2026.10.26 の default 追加部品が `certifi>=2026.10.19` を要求するため、pip が必要な更新として上げる |
| 古い yt-dlp が入っている場合 | -U で yt-dlp 自体が最新に上がるため、同じ経路で certifi も上がる（上の手順は yt-dlp 未導入の環境での結果。「旧版 yt-dlp が入った環境」は未再現） |
| Python 3.10 の利用者（実機は無く、`pip download --python-version 3.10` で確認） | 取得できる最新は yt-dlp 2026.10.21（Requires-Python >=3.10）。これも `certifi>=2026.10.19` を要求するので、certifi は守られる。ただし 2026.10.26 以降は受け取れない |

### 結論
- 研究課の推測（setup.bat だけでは古い certifi が上がらない）は、yt-dlp 2026.10.21 以降が入る限り**当てはまらない**。setup.bat の修正は必須ではない。
- 残る穴（未検証）：①yt-dlp を入れずに他だけ使う場合、②利用者が `pip install` に失敗した場合。どちらも通常の手順では起きにくい。
- 任意の補強案（開発課の判断）：setup.bat の `%PY% -m pip install -U "yt-dlp[default]" ...` の行に `"certifi>=2026.10.19"` を足す（同じ行の末尾、または直前に1行）。入っても害はなく、要求が明示される。
