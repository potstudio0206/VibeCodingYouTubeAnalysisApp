# 書類

| フォルダ | 担当 | 内容 |
|---|---|---|
| `00_status/` | 部長・課長 | 進捗ボード、決定メモ |
| `01_research/` | 研究課 | ライブラリ仕分け表、動向レポート、研究レポート |
| `02_requirements/` | 要件定義課 | 現状仕様書、開発後の仕様書、要件定義書（REQ） |
| `03_design/` | 設計課 | 基本設計書（BD）、詳細設計書（DD・MVVM） |
| `04_refactoring/` | リファクタリング課 | リファクタリング計画書（RF） |
| `05_dev/` | 開発課 | テスト仕様書（TS） |
| `06_qa/` | 品質保証課 | 保守運用書、テスト結果報告書（QA） |
| `07_ops/` | 保守運用課 | 運用記録、障害記録（INC）、フィードバックまとめ（FB） |
| `08_player/` | プレイヤー代理課 | プレイヤー要望書（PLY）、試用メモ |
| `90_handbook/` | 社長向け | 使い方、PCの準備、定期実行、エージェントチーム |

書類の流れ（1つの案件）：REQ → BD → DD →（RF）→ 実装 → TS → QA → PR。番号は REQ のものを引き継ぎます。
両部で共通の指標の定義は、リポジトリ直下の `shared/metrics-spec.md` にあります。
