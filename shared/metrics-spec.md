# 共通指標仕様書（チャット指標） v1.0.0

in App版（Python）と in Chrome版（JavaScript）が**同じ値を出さなければならない**チャット指標の定義です。
この文書と `golden/` の基準データが唯一の正であり、両版の実装はこれに合わせます。
一致しているかどうかは、各リポジトリの適合テストで自動確認します。

- in App版：`tests/test_shared_spec.py`
- in Chrome版：`tests/unit/shared_spec.test.js`

## 0. この仕様書の扱い

- `shared/` フォルダは **両リポジトリで完全に同じ内容** を保ちます。片方だけを変更してはいけません。
- 変更は要件定義課が両リポジトリへ同時にPRを出して行います。変更前に、社長の承認（判断待ちIssue）が必要です。
- 変更したら `VERSION` を上げて、参照実装で基準データを作り直します（`python shared/reference/metrics_ref.py --write-golden`）。
- 手順は、各リポジトリのスキル `/shared-spec` に従います。

## 1. 対象とする指標

| 指標 | 英名（実装上の名前） | 意味 |
|---|---|---|
| コメント量 | `count` | 区間内に流れたコメントの件数 |
| 加速度 | `accel` | 直前の区間からのコメントの増え方（平常時の量で割ったもの） |
| 同じコメントの流れる確率 | `same_rate` | 区間内で一番多いコメントが、全コメントに占める割合 |

盛り上がりスコア、見どころの選び方、キーワードの分類、声・画面の指標は**各版の固有仕様**です。この文書の対象外です。

## 2. 入力：チャット項目の読み取り

### 2.1 元データ

YouTubeのチャットリプレイの各アクション（`replayChatItemAction`）を読みます。
in App版では yt-dlp が保存する `<動画ID>.live_chat.json` の各行が、in Chrome版では `get_live_chat_replay` の応答に含まれる `actions` の各要素が、1つのアクションです。

### 2.2 時刻

- `t = videoOffsetTimeMsec ÷ 1000`（秒）。**丸めない**こと。
- `videoOffsetTimeMsec` が無い、空、数値にできない、または負の場合、そのアクションは捨てます。

### 2.3 種類

`addChatItemAction.item` に含まれるレンダラーの種類で、次のように分けます。ここに無い種類は捨てます。

| 種類 | レンダラー |
|---|---|
| `text`（通常コメント） | `liveChatTextMessageRenderer` |
| `money`（スーパーチャット等） | `liveChatPaidMessageRenderer`、`liveChatPaidStickerRenderer` |
| `member`（メンバー加入・ギフト） | `liveChatMembershipItemRenderer`、`liveChatSponsorshipsGiftPurchaseAnnouncementRenderer` |

### 2.4 本文

- `member` の本文は空文字です。
- それ以外は `message` から作ります。
  - `simpleText` があり空でなければ、それを本文とします。
  - 無ければ、`runs` を順に連結します。各要素は次の順で判定します。
    - `text` が空でなければ、その文字列を使います。
    - そうでなく `emoji` があれば、`isCustomEmoji` が真で `shortcuts` が空でないとき先頭のショートカット（例 `:_kusa:`）、それ以外は `emojiId`（無ければ空文字）を使います。
    - どちらでもなければ、何も足しません。
  - `message` が無ければ空文字です。
- **本文は切り詰めません**（切り詰めは 3.1 の正規化でのみ行います）。

### 2.5 重複と並び順

- レンダラーの `id` が既に出てきたものと同じなら、その項目は捨てます（最初の1件だけ残す）。
- 項目は `t` の昇順に並べます。同じ `t` の項目は、元データでの出現順を保ちます。

## 3. 計算

### 3.1 正規化（同じコメントかどうかの判定キー）

本文 `s` から判定キーを作ります。手順の順番も仕様の一部です。

1. Unicode正規化 NFKC（全角英数→半角など）
2. 小文字化
3. 前後の空白を除く
4. 連続する空白を半角スペース1つにする
5. 同じ文字が4回以上続く部分を、3回にする（`wwwww` → `www`、`88888` → `888`）
6. 先頭30文字（コードポイント単位）に切り詰める

結果が空文字なら、その項目は判定キーを持ちません（件数には数えます）。

### 3.2 区間

- 区間の長さ `BIN`（秒）は各版の設定値です（既定は両版とも30秒）。
- 動画の長さ `D` は動画情報の長さ（秒）です。不明（0）の場合は、並べた後の最後の項目の `t` を使います。
- 区間数 `N = max(1, ceil(D ÷ BIN))`
- 項目の区間番号は `min(N − 1, floor(t ÷ BIN))` です（`D` より後の項目は最後の区間に入れます）。
- `t < 0` の項目は数えません。

### 3.3 コメント量 `count[i]`

区間 `i` に入る `text` と `money` の項目の件数です。`member` は数えません。

### 3.4 平常時の量 `base[i]`

- `count` の移動中央値に下限1を付けたものです：`base[i] = max(1, median(count[max(0, i−10) .. min(N−1, i+10)]))`
- 窓は前後10区間（端では短くなります）。
- 中央値は、要素数が偶数のとき中央2つの平均です。

### 3.5 加速度 `accel[i]`

- `accel[0] = 0`
- `accel[i] = (count[i] − count[i−1]) ÷ base[i]`（`i ≥ 1`）

### 3.6 同じコメントの流れる確率 `same_rate[i]`

- `top[i]`：区間 `i` で判定キーごとに件数を数えたときの最大件数（判定キーを持つ項目だけが対象）
- `count[i] ≥ 5` かつ `top[i] ≥ 3` のとき `same_rate[i] = top[i] ÷ count[i]`、それ以外は `0`

## 4. 出力と許容差

- 出力は `count`（整数配列）、`accel`・`same_rate`（実数配列）、区間数 `N` です。
- 画面表示や保存のために、実数を小数第3位に丸めてもかまいません。
- 適合テストの許容差は、`count` と `N` が完全一致、実数は絶対誤差 0.0011 以内です。
